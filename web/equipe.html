L'équipe

Les agents Grok au service de la solution KermicLab. Les six membres de l'équipe présentés ici sont des agents d'intelligence artificielle. Ils travaillent en coulisse pour faire fonctionner et améliorer KermicLab, au service des enfants, des parents et des enseignants.

  • Émile Grok

    Orchestrateur KermicLab

    Émile coordonne l'ensemble des agents KermicLab. Il répartit les tâches, veille à la cohérence des travaux et cherche à améliorer les processus : développement, contenu, documentation, veille et synchronisation.

    Compétences clés : vision globale du projet, orchestration, synthèse, communication entre agents.

  • Inès Grok

    Auditrice d'agents

    Inès surveille, analyse et audite l'activité des autres agents, pour garantir la qualité, la cohérence et l'efficacité de leur travail.

    Compétences clés : analyse des comptes rendus d'activité, détection d'écarts, rapports clairs, amélioration continue.

  • Chloé Grok

    KermicLab Contenu Tunnel

    Chloé crée et affine les contenus qui présentent KermicLab, de la première découverte jusqu'à la décision, en restant alignée avec la vision pédagogique, le respect de la vie privée et l'offre freemium.

    Compétences clés : rédaction, storytelling éducatif, adaptation à chaque étape du parcours d'information, cohérence de marque.

  • Paul Grok

    KermicLab Notion Docs

    Paul maintient la documentation Notion de KermicLab à jour, en la synchronisant avec le dépôt GitHub du projet.

    Compétences clés : structuration documentaire, synchronisation GitHub et Notion, clarté rédactionnelle, maintenance continue.

  • Hugo Grok

    KermicLab GitHub-Grok Sync

    Hugo assure la cohérence, dans les deux sens, entre le dépôt GitHub kermic974/kermiclab et l'environnement de travail Grok. Il surveille les mises à jour et veille à ce que les fichiers, la documentation et le code restent alignés.

    Compétences clés : Git, synchronisation, détection de divergences, maintenance de la cohérence.

  • Manon Grok

    KermicLab Veille Marché

    Manon assure la veille concurrentielle et de marché pour KermicLab, autour des solutions éducatives interactives et du curriculum français (CM1, CM2, 6e et au-delà). Elle en tire des analyses de positionnement et des recommandations.

    Compétences clés : veille, analyse concurrentielle, synthèse stratégique, recommandations actionnables.

Les autres intelligences artificielles

Ces rôles viennent du contrat de répartition des rôles IA, version 0.9. Ce texte est soumis à revue : il n'est pas encore approuvé et ne s'applique pas encore. Le propriétaire du projet reste le décideur final.

Grok, déjà présenté par les six agents ci-dessus, explore aussi l'environnement externe de KermicLab : tendances, solutions existantes, alternatives et angles nouveaux. Il ouvre le champ des possibilités avant la décision.

Notion, GitHub et Cloudflare figurent dans le même contrat comme espace de documentation, référence technique et infrastructure. Ce ne sont pas des agents d'intelligence artificielle.

  • ChatGPT

    Architecte de cadrage et de décisions

    ChatGPT transforme une intention, une problématique ou des informations exploratoires en problème structuré, options, architecture conceptuelle, décisions proposées, spécification initiale, critères d'acceptation et plan de travail. Il assure le cadrage conceptuel initial. Il n'est pas réputé connaître un dépôt qu'il n'a pas effectivement analysé.

    Responsabilités clés : clarification du besoin, structuration des problèmes, conception fonctionnelle, options architecturales, critères d'acceptation.

  • Gemini

    Contre-expert analytique et auditeur de conception

    Gemini fournit un regard indépendant sur les décisions et les spécifications importantes, afin d'identifier les incohérences, les hypothèses fragiles, les angles morts, les cas limites et les risques. Son avis ne constitue pas, à lui seul, une validation finale.

    Responsabilités clés : audits contradictoires, mise à l'épreuve des hypothèses, cohérence d'ensemble, risques conceptuels, amendements.

  • M365 Copilot

    Co-rédacteur, intégrateur documentaire et gardien de cohérence fonctionnelle

    M365 Copilot travaille avec le propriétaire du projet pour transformer les décisions validées en référentiel fonctionnel cohérent, structuré et exploitable, notamment dans le bloc-notes KermicLab. Il construit et maintient le corpus de spécifications. Ce rôle est distinct du cadrage assuré par ChatGPT.

    Responsabilités clés : co-rédaction des spécifications, consolidation des décisions, cohérence entre sections, terminologie, contrats destinés aux agents de développement.

  • Claude Code

    Agent principal d'ingénierie et d'implémentation

    Claude Code transforme une spécification suffisamment stabilisée en modifications techniques effectives. Il confronte les spécifications à l'architecture réelle du dépôt. Il ne modifie pas en silence une règle fonctionnelle pour faciliter l'implémentation.

    Responsabilités clés : analyse du dépôt, plan d'implémentation, modifications portant sur plusieurs fichiers, tests, signalement des incompatibilités.

  • GitHub Copilot

    Copilote de développement interactif

    GitHub Copilot accompagne le propriétaire du projet dans le développement plus localisé, directement dans l'environnement de développement. Claude Code reçoit une mission d'ingénierie relativement autonome ; GitHub Copilot accompagne une session interactive ou une modification ciblée.

    Responsabilités clés : assistance au codage, petites évolutions, corrections localisées, tests ciblés, explication du code.

  • Symphony by Wix

    Orchestrateur des activités business et opérationnelles

    Symphony intervient dans le développement de l'activité autour de KermicLab, plutôt que dans la construction de son architecture logicielle.

    Responsabilités clés : marketing, prospection, opérations, recherche commerciale, activités de croissance.

Other artificial intelligences

These roles come from the AI role-allocation contract, version 0.9. That text is under review: it is not yet approved and does not yet apply. The project owner remains the final decision-maker.

Grok, already introduced through the six agents above, also explores the environment around KermicLab: trends, existing solutions, alternatives and new angles. This opens the field of possibilities before a decision.

The same contract also describes Notion, GitHub and Cloudflare, as a documentation space, the technical reference and the infrastructure. They are not artificial intelligence agents.

  • ChatGPT

    Framing and decision architect

    ChatGPT turns an intention, a problem or exploratory information into a structured problem, options, a conceptual architecture, proposed decisions, an initial specification, acceptance criteria and a work plan. It handles the initial conceptual framing. It is not assumed to know a repository it has not actually analysed.

    Key responsibilities: clarifying the need, structuring problems, functional design, architectural options, acceptance criteria.

  • Gemini

    Analytical counter-expert and design auditor

    Gemini provides an independent view of important decisions and specifications, in order to identify inconsistencies, fragile assumptions, blind spots, edge cases and risks. Its opinion is not, on its own, a final validation.

    Key responsibilities: contradictory audits, stress-testing assumptions, overall consistency, conceptual risks, amendments.

  • M365 Copilot

    Co-author, documentary integrator and guardian of functional consistency

    M365 Copilot works with the project owner to turn validated decisions into a coherent, structured and usable functional reference, notably in the KermicLab notebook. It builds and maintains the body of specifications. This role is distinct from the framing done by ChatGPT.

    Key responsibilities: co-writing specifications, consolidating decisions, consistency across sections, terminology, contracts for the development agents.

  • Claude Code

    Principal engineering and implementation agent

    Claude Code turns a sufficiently stable specification into actual technical changes. It compares specifications with the real architecture of the repository. It does not silently change a functional rule to make implementation easier.

    Key responsibilities: repository analysis, implementation plan, changes across several files, tests, reporting incompatibilities.

  • GitHub Copilot

    Interactive development copilot

    GitHub Copilot assists the project owner with more local development, directly in the development environment. Claude Code receives a relatively autonomous engineering mission; GitHub Copilot assists an interactive session or a targeted change.

    Key responsibilities: coding assistance, small changes, local fixes, targeted tests, explaining code.

  • Symphony by Wix

    Orchestrator of business and operational activities

    Symphony works on developing the activity around KermicLab, rather than on building its software architecture.

    Key responsibilities: marketing, prospecting, operations, commercial research, growth activities.

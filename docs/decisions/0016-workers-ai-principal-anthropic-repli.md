# ADR 0016 — Workers AI principal, Anthropic en repli

- Date : 2026-11-05 — Statut : accepté
- Contexte : le propriétaire souhaite Workers AI actif, Anthropic en repli et une comparaison ultérieure, avec garde-fous de budget, périmètre et traçabilité.
- Décision :
  1. Le Worker utilise le binding Cloudflare `AI` en premier, avec `@cf/meta/llama-3.3-70b-instruct-fp8-fast` et le mode JSON Schema.
  2. Le binding ne nécessite pas de clé API. La clé Cloudflare sert au déploiement uniquement ; l'accès au modèle et sa consommation relèvent du compte Cloudflare.
  3. Si Workers AI échoue et que `ANTHROPIC_API_KEY` est configurée, Claude Haiku 5.5 est appelé en repli, **si le quota restant le permet**. Une réponse de refus ou hors périmètre ne déclenche pas de second fournisseur.
  4. Les fournisseurs ne sont pas appelés en parallèle. La comparaison croisée reste une évolution future, soumise au même quota et aux mêmes droits.
  5. Une session est limitée à **1 000 tokens générés**, tous essais compris, JSON et sorties refusées inclus ; les tokens d'entrée n'entrent pas dans cette limite (choix explicite du propriétaire). Chaque essai réserve atomiquement au plus 500 tokens dans D1. Le reliquat mesuré est libéré ; en cas d'erreur ou d'usage inconnu, la réservation entière est consommée par prudence. Les nouvelles tentatives automatiques Anthropic sont désactivées. Un appel interrompu avant règlement conserve sa réservation verrouillée : on ne libère jamais un budget dont la consommation est inconnue.
  6. Le contexte est la dernière page du catalogue servie à la session via le chat. Seules des relances fermées (« Explique plus simplement », « Donne-moi un exemple », « Propose un petit défi » et équivalents anglais) permettent un appel. Les autres questions ouvrent une page locale ou sont refusées sans appel. Ni ID de source ni historique arbitraire du client ne peuvent ouvrir le périmètre. La génération libre hors catalogue et les issues automatiques associées sont donc suspendues ; les demandes de nouvelles pages restent possibles via GitHub.
  7. Le modèle reçoit un extrait textuel borné de la page, sans scripts/styles, et une relance canonique ; pas de recherche web ni d'historique de conversation. Les sources citées doivent correspondre à cette page. Le Worker construit lui-même les liens, descriptions et versions. Le chat les affiche en fin de réponse avec le fournisseur réellement utilisé, le modèle, la version du harness et du prompt, le mode d'accès, le quota et le comptage de chaque essai. Les sources restent visibles ; les autres métadonnées sont repliées derrière un chevron « Détails techniques » pour ne pas surcharger le fil.
  8. `LLM_ACTIF=true` et le secret `LLM_SESSION_SECRET` (au moins 32 caractères aléatoires) sont nécessaires. Le cookie technique signé est `HttpOnly; Secure; SameSite=None; Path=/`, sans durée de persistance navigateur. Expiration serveur absolue de 24 h, même si le navigateur restaure la session. Sans cookie valide, pas d'appel. D1 ne conserve qu'un ID aléatoire, une expiration, un ID de page et des compteurs ; purge quotidienne des sessions expirées (rétention maximale d'environ 48 h).
  9. L'accès reste **gratuit provisoirement**. Le contrôle par abonnement est au [backlog paiement](../chantiers/tva-paiement.md) et devra s'exécuter côté serveur avant toute réservation, pour tous les fournisseurs. Il n'est pas présenté comme déjà opérationnel.
  10. Tous les appels pédagogiques passent par **`kermiclab-gateway`** : options gateway du binding pour Workers AI, URL fournisseur de cette gateway pour le SDK Anthropic. Aucun repli direct ne contourne la gateway. Cache et logs désactivés, un seul essai gateway par réservation ; aucun retry/fallback supplémentaire ne doit être configuré dans Cloudflare. Le repli Anthropic exige aussi `AI_GATEWAY_TOKEN` (permission AI Gateway Run), sans quoi il est indisponible avant réservation.
- Limites : sans compte, la suppression du cookie ou un autre navigateur crée une autre session. Ce quota n'est pas un plafond par personne ou une garantie de coût global. Les tokens d'entrée restent facturables. Le périmètre fermé et la validation des références réduisent les dérives mais ne prouvent pas l'exactitude de chaque phrase générée ; une validation pédagogique humaine reste nécessaire.
- Conséquences : le routage par mots-clés reste sans appel modèle. Le propriétaire doit vérifier les tarifs/quota Cloudflare, les conditions des fournisseurs et le cookie technique avant activation. Aucune clé utilisateur n'est demandée dans le chat.
- English summary: Workers AI is primary, Anthropic is an optional failure fallback. A signed browser-session cookie (absolute server expiry: 24 hours) identifies an anonymous, atomic D1 budget of 1,000 output tokens across all attempts, including failures and fallback. Unknown usage is conservatively charged, SDK retries are disabled, and only canonical follow-ups on the last server-served catalogue page can call a model. Trusted page links, descriptions and actual model/harness metadata appear after each answer. Access is temporarily free; server-side subscription gating is planned, not implemented. Cookie deletion can create another anonymous session; input tokens and total spend are not capped by this policy.
- Références : [documentation Cloudflare JSON Mode](https://developers.cloudflare.com/workers-ai/features/json-mode/), [tarifs Workers AI](https://developers.cloudflare.com/workers-ai/platform/pricing/).
- Gateway (English): Workers AI and the Anthropic SDK fallback must use `kermiclab-gateway`, with no direct-provider bypass. Requests disable caching and log collection and allow only one gateway attempt. The fallback also requires an AI Gateway Run token; disable payload exports and additional gateway retries/fallbacks in the dashboard.
- Références gateway : [binding Workers](https://developers.cloudflare.com/ai-gateway/usage/worker-binding-methods/), [SDK Anthropic](https://developers.cloudflare.com/ai-gateway/usage/providers/anthropic/), [logs](https://developers.cloudflare.com/ai-gateway/observability/logging/), [retries](https://developers.cloudflare.com/ai-gateway/configuration/request-handling/).

# ADR 0019 — Configuration centralisée des modules

- Date : 2026-11-06 — Statut : accepté
- Contexte : les paramètres réglables étaient dispersés entre `session-llm.js` (budget de 1 000 tokens par session, 500 par appel, en dur), `defi-llm.js` (générations par jour, 1 500 tokens par génération, harness), `llm.js` (modèles et alias par défaut), `contexte-llm.js` et `cadrage-idee.js` (harness des prompts) et `index.js` (taille des messages, limite de débit). L'écran Configuration ne montrait que deux réglages personnels. Le propriétaire demande de centraliser les paramètres configurables des modules (alias, taille de tokens min–max, skills…).
- Décision :
  1. **Registre unique** `worker/src/configuration.js` : chaque paramètre déclare sa clé (variable `[vars]` de `worker/wrangler.toml`), son module (`general`, `tuteur`, `defi`), son type (`booleen`, `entier`, `alias`, `liste`), son défaut et, pour les entiers, ses bornes min–max. `lireConfiguration(env)` renvoie les valeurs effectives : absentes ou invalides → défaut ; entiers hors bornes → bornés ; alias limités à `[A-Za-z0-9@/._:-]` (100 caractères). `MAX_TOKENS_APPEL` ne dépasse jamais `LIMITE_TOKENS_SESSION`.
  2. **Paramètres** : `LLM_ACTIF`, `SKILLS_ACTIFS`, `TAILLE_MAX_MESSAGE` (50–2000), `LIMITE_PAR_MINUTE` (1–120) ; tuteur et boîte à idées : `MODELE_WORKERS_AI`, `MODELE_CHAT`, `LIMITE_TOKENS_SESSION` (200–4000, défaut 1 000), `MAX_TOKENS_APPEL` (100–1000, défaut 500) ; défi : `MODELE_DEFI` (alias AI Gateway), `DEFI_GENERATIONS_JOUR` (0–10), `MAX_TOKENS_DEFI` (500–3000, défaut 1 500) ; Mes cahiers (module `cahiers`, ajouté ensuite) : `MODELE_CAHIERS` (alias AI Gateway, défaut `custom/sonnet-5-5`), `MAX_TOKENS_CAHIERS` (1 000–128 000, défaut 100 000). Les défauts reprennent exactement les valeurs précédentes : aucun changement de comportement sans modification de `wrangler.toml`.
  3. **Skills** : chaque consigne système versionnée (`tuteur-catalogue-v1`, `cadrage-idee-v1`, `defi-express-v1`) est déclarée dans le registre `SKILLS` et sert de harness aux métadonnées de réponse. `SKILLS_ACTIFS` (liste séparée par des virgules, tous par défaut) coupe un skill sans toucher aux autres : un skill retiré n'appelle aucun modèle (tuteur → réponse sans modèle, cadrage → indisponible, défi → banque fixe). `LLM_ACTIF=false` reste l'arrêt d'urgence global.
  4. **Vue publique** : `GET /api/llm/status` ajoute `skills` (disponibilité effective par skill) et `configuration` (modules, paramètres avec valeur, défaut et bornes, skills actifs). Aucune variable secrète n'est lue par le registre ni exposée ; un test le vérifie.
  5. **Écran Configuration** : sous les choix personnels (« Utiliser l'IA », défis par jour), un bloc « Paramètres du site » affiche en lecture seule ces paramètres par module, avec leurs bornes et l'état des skills. Les réglages restent faits par l'administrateur dans `wrangler.toml` ; le navigateur ne peut rien modifier.
- Limites : un changement de paramètre nécessite un redéploiement du Worker (variables `[vars]`). Les libellés de l'interface sont traduits par clé (`configParam_<CLÉ>`, `configSkill_<id>`) : ajouter un paramètre demande d'ajouter ses libellés dans toutes les langues (le lint vérifie la parité).
- English summary: all tunable Worker settings (model aliases, token budgets with min–max bounds, quotas, per-skill switches) now live in one registry, `worker/src/configuration.js`, read from `wrangler.toml` `[vars]` with defaults equal to the previous hard-coded values and clamping. `SKILLS_ACTIFS` turns individual LLM skills off. `/api/llm/status` exposes the non-secret effective configuration, shown read-only, per module, in the Settings screen.
- Références : ADR 0016, ADR 0018.

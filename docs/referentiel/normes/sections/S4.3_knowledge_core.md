# S4.3 — Contrats du Knowledge Core : Notion, MicroSkill, Skill

| Section | Version | Statut | Dépend de |
|---|---|---|---|
| S4.3 (numéro proposé) | 1.2.0 | 🟢 ADOPTÉE | S2, S4.1, S4.2 |

## 1. Structures communes [P]

**`LocalizedText`** — objet fermé dont les clés sont des codes de langue ISO 639-1 (`^[a-z]{2}$`) et les valeurs des chaînes non vides. La clé `fr` est obligatoire.

| Usage | Longueur de chaque valeur |
|---|---|
| `label` | 1 à 200 caractères |
| `description` | 1 à 2000 caractères |

**[R]** Le produit existant est bilingue (`web/i18n/fr.json`, `en.json`) ; le français fait foi.

## 2. Contrat Notion

| Champ | Obligatoire | Type | Règle | Origine |
|---|---|---|---|---|
| `id` | oui | ID | namespace `notion` | [B] |
| `type` | oui | constante | `"notion"` | [B] |
| `label` | oui | LocalizedText | — | [B] champ ; [P] forme |
| `status` | oui | énumération | S4.2 | [B] |
| `version` | oui | entier ≥ 1 | S4.2 | [B] |
| `description` | non | LocalizedText | — | [P] |
| `replacedBy` | non | ID `notion` | S4.2 §6 | [B] |
| `provenance` | non | Provenance | S4.7 | [P] |

Champs d'identité (immuables, `S4-ID-010`) : `id` seul. **[D]** Le libellé peut changer sans changer d'identité ; la rupture sémantique se juge en revue.

Interdit **[B]** : toute propriété exprimant une relation (prérequis, compétences) ou un positionnement curriculaire (niveau, classe, cycle). La fermeture du contrat suffit à l'interdire.

## 3. Contrat MicroSkill

Mêmes champs que Notion, avec `type = "microskill"`, namespace `microskill`, `replacedBy` vers `microskill`. **[B]**

## 4. Contrat Skill

Mêmes champs que Notion, avec `type = "skill"`, namespace `skill`, `replacedBy` vers `skill`. **[B]**

## 5. Exemple (normatif)

```json
{
  "id": "notion.mathematiques.theoreme-de-pythagore",
  "type": "notion",
  "label": { "fr": "Théorème de Pythagore", "en": "Pythagorean theorem" },
  "status": "draft",
  "version": 1
}
```

## 6. Règles

| Rule ID | Niveau | Sévérité | Origine | Règle |
|---|---|---|---|---|
| S4-KC-001 | 2 | ERROR | B | Une Notion respecte son contrat : champs obligatoires présents, types des champs (la valeur de `type` relève de `S4-ID-003`). |
| S4-KC-002 | 2 | ERROR | B | Une MicroSkill respecte son contrat (même règle que `S4-KC-001`). |
| S4-KC-003 | 2 | ERROR | B | Une Skill respecte son contrat (même règle que `S4-KC-001`). |
| S4-KC-004 | 2 | ERROR | P | `label` et `description` sont des LocalizedText valides (clé `fr` présente, clés ISO 639-1, longueurs). |
| S4-KC-005 | 4 | ERROR | B | Une MicroSkill `validated` est la cible d'au moins une Relation `teaches` `validated` dont la source est une Notion `validated`. |
| S4-KC-006 | 4 | ERROR | B | Une Skill `validated` est la cible d'au moins une Relation `contributesTo` `validated` dont la source est une MicroSkill `validated`. |
| S4-KC-007 | 4 | WARNING | P | Une Skill `validated` ne reçoit la contribution que d'une seule MicroSkill (frontière MicroSkill / Skill, S2 §4). |

**[P]** Pour `S4-KC-005` et `S4-KC-006`, une source devenue `deprecated` après coup laisse la condition non satisfaite : c'est un WARNING (`S4-REF-004`), pas une ERROR, conformément à S4.2 §7.
